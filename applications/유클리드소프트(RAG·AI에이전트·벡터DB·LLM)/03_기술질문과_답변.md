## 3. 거리 임계값 0.45의 근거는 무엇인가요?

**코드·실행 결과**: ChromaDB 컬렉션을 cosine 거리로 설정하고 Top-3를 검색한 뒤 `distance ≤ 0.45`만 통과시켰습니다. 실행 기록에는 관련 질문 0.1766·0.3434·0.4489, 무관·범위 밖 질문 0.3439·0.3660·0.4441·0.4922·0.6292가 함께 나타납니다. 따라서 0.45는 일부 테스트를 바탕으로 정한 소규모 휴리스틱 기준이며, 관련·무관 질문을 완전히 분리하는 통계적 최적값은 아닙니다.

**확인할 자료**: `RAG/rag_server/rag_pipeline.py`, 임베딩 노트북의 검색 셀, 환각 테스트 기록. 노트북 설명에는 기본값 `0.40`이 남아 있지만 실행 상수와 서버 코드는 `0.45`이므로 면접에서는 실제 서버 기준을 `0.45`로 설명하고 문서 버전 차이를 인지합니다.

**답변 틀**

> ChromaDB cosine distance와 Top-3를 사용하고 `0.45`를 기준으로 삼았습니다. 존재하지 않는 메뉴처럼 0.45를 넘는 질문은 LLM 호출 없이 거절할 수 있지만, 무관 질문이 0.45 이하로 들어오는 경우도 있어 프롬프트와 생성 결과를 별도로 검증해야 합니다. 따라서 이 값은 소규모 테스트 기반의 운영 기준이지 정확도를 보장하는 경계값은 아닙니다.

괄호를 실제 근거로 채우기 전에는 완성된 답변으로 사용하지 않습니다. 단순 사례 확인이었다면 정량 평가를 수행한 것처럼 말하지 않습니다.

## 6. LoRA와 RAG를 함께 사용한 이유는 무엇인가요?

**문서 기반 답변**

> Bllossom-3B를 MLX 기반 LoRA로 파인튜닝했습니다. 설정·어댑터 공통 기록은 500 iterations, batch size 4, learning rate 2e-5, 16개 레이어, 최대 길이 512, seed 42, rank 8, `mask_prompt=true`입니다. train 1,672건·valid 53건·test 10건은 설정 경로와 저장소 사본이 일치합니다. 다만 scale·dropout은 YAML 최상위와 adapter 내부 기록이 달라 유효값을 확정하지 않습니다. 파인튜닝 단독에서는 없는 메뉴 질문에 거짓 답변이 나와, 최신 사실의 근거 제공과 거절 처리는 RAG로 분리했습니다.

**확인 필요**: README에는 `80개 대화`, 250 iterations·learning rate 1e-5 표기가 있어 현재 실행 산출물과 버전 차이가 있습니다. scale·dropout의 유효값도 학습 당시 MLX 버전과 실행 로그를 확인해야 합니다. RAG 테스트는 10개 케이스이며 복합 질문·잘못된 생성 결과가 남아 있습니다.

## 8. preview·rollback·commit은 어떻게 다른가요?

**문서 기반 답변**

> preview는 준비된 적재 payload를 JSONL로 출력하고 MySQL INSERT DB에는 접속하지 않습니다. 다만 기본 실행에서는 Oracle 키워드 조회가 먼저 필요하며, `--offline-keywords`를 사용할 때만 Oracle도 생략합니다. rollback은 실제 INSERT SQL을 실행한 뒤 행 단위 롤백하고, commit은 행 단위 커밋합니다. 세 모드가 같은 준비 객체를 공유하도록 구성했습니다.

**설명할 한계**: 이미 커밋된 행은 뒤에서 발생한 롤백만으로 되돌아가지 않습니다. 행 단위 커밋을 선택한 이유, 부분 성공을 어떻게 확인하고 복구하는지 구분합니다.

**확인 필요**: 현재 중복 판별 기준, 재처리 상태 저장 방식, 동시 실행 처리. 이를 확인하기 전 정확히 한 번 처리(Exactly-once)를 보장했다고 말하지 않습니다.
