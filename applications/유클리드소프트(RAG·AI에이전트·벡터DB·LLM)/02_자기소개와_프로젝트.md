# 유클리드소프트 — 자기소개와 프로젝트 설명

작성일: 2026-09-04. 상태: 문서 근거 기반 답변 초안. 말하기 시간은 목표이며 실측하지 않았습니다.

## 1. 자기소개 — 약 40초 목표

> 안녕하세요. 데이터 수집·적재와 분석 환경을 구축해 온 데이터 엔지니어 이영선입니다. 최근에는 HK이노엔 AI 챗봇의 수집·적재 파트를 단독으로 맡아 문서 추출과 LLM 연동을 구현했습니다. 실제 입력 데이터를 분석해 불필요한 내용을 줄이고, 반복되던 요약 타임아웃을 해결한 경험이 있습니다. 개인 프로젝트에서는 RAG와 LoRA 파인튜닝을 활용한 챗봇을 개발했습니다. 데이터 파이프라인 경험을 바탕으로 검색과 응답 품질까지 개선하는 AI 엔지니어로 기여하고 싶습니다.

근거: 이력서의 실무 경력·AI/ML 프로젝트, 자기소개서 2장. 마지막 문장은 지원 방향에 대한 제안이므로 본인 의사 확인 후 사용합니다.

## 2. 지원 동기 — 약 40초 목표

> 이번 공고는 데이터 수집·전처리부터 RAG 시스템 개발과 검색·응답 품질 평가까지 연결되어 있어 지원했습니다. 저는 실무에서 AI에 공급할 데이터를 수집하고 정제하는 계층을 맡았고, 개인 프로젝트에서는 임베딩과 벡터 DB를 사용하는 RAG를 구현했습니다. 이 경험을 바탕으로 데이터가 검색되고 답변에 활용되는 과정까지 책임지는 역할로 확장하고 싶습니다.

확인 필요: 실제 지원 동기와 일치하는지 확인합니다. 회사 자체에 관심을 가진 이유가 있다면 확인된 사실 한 가지를 추가합니다.

## 3. DE에서 AI로 전환하는 이유 — 약 40초 목표

> 법학을 전공한 뒤 개발로 진로를 바꿨고, 재직 중 컴퓨터공학 학사를 취득하며 기반을 다졌습니다. 데이터 엔지니어링 업무를 하면서 데이터를 수집하고 정제해 실제 서비스에서 활용할 수 있도록 만드는 일을 해왔습니다. 최근에는 AI 챗봇 데이터 파이프라인과 개인 RAG 프로젝트를 경험했습니다. 그동안 쌓은 데이터 처리 경험을 바탕으로 검색과 생성까지 다루는 방향으로 역할을 넓히고 싶습니다.

근거: 자기소개서 ABOUT ME와 4장. 경험을 나열하기보다 현재 지원 업무와 연결합니다.

## 4. HK이노엔 — 2분 이내 설명

### 답변 초안

> HK이노엔 AI 챗봇에 공급할 데이터의 수집·적재를 단독으로 담당했습니다. 외부 규제 정보를 수집하는 파이프라인과, 사내 6개 기간계 시스템의 데이터를 옮기는 내부 ETL로 나뉩니다.
>
> 외부 수집에서는 5개 도메인 25개 게시판을 처리하고, PDF·HWP·HWPX·DOCX·XLSX·ZIP 6종 첨부에서 본문을 추출했습니다. 특히 LLM 요약 단계의 타임아웃을 해결하는 과정이 중요했습니다. 실제 입력을 측정해 보니 자재명 부분 문자열 매칭으로 대형 표 전체가 입력되고 있었습니다. 첨부에 자사 상호가 있는 경우 회사명으로 관련 내용을 선별하도록 바꿨습니다. 그 결과 HWPX 사례에서는 79,692자에서 514자로, PDF 사례에서는 64,026자에서 223자로 입력을 줄였습니다.
>
> 적재는 preview·rollback·commit 모드로 나누고 행 단위 트랜잭션과 단위 테스트 71개로 검증 체계를 구성했습니다. 내부 수집에서는 메타데이터로 2,000개 이상의 Hive External Table DDL을 자동 생성했습니다. 제 핵심 기여는 데이터가 AI에 전달되기 전의 수집·정제·적재 과정을 구현하고, 장애 원인을 실제 입력과 실행 결과로 확인해 해결한 점입니다.

### STAR와 근거

| 구분 | 말할 내용 |
| :--- | :--- |
| 상황·과제 | 외부 규제 문서와 내부 기간계 데이터를 챗봇용으로 확보해야 했습니다. |
| 행동 | 첨부 추출, 회사명 기반 선별, 안전 실행 모드, 메타데이터 기반 DDL 생성을 구현했습니다. |
| 결과 | 입력 155배·287배 축소 사례, DDL 2,000개+, 테스트 71개를 문서에 기록했습니다. |
| 근거 | 경력기술서 1-1~1-6, 자기소개서 1~3장. |

확인 필요: 두 입력 축소 사례의 원본·실행 결과, 관련 정보 누락 검증 방법, 장애 해소 관찰 기간. 증분 적재와 마트 구성의 현재 완료 여부도 확인합니다.

## 5. 위니쿠키 — 확인된 설명과 보충할 내용

### 확인된 범위의 답변 초안

> 위니쿠키는 개인적으로 개발한 AI 챗봇입니다. Bllossom-3B를 Apple Silicon 환경에서 MLX 기반 LoRA로 파인튜닝했고, ChromaDB와 bge-m3를 활용한 RAG 파이프라인을 FastAPI로 구성해 Discord 봇과 연동했습니다. 검색 결과에는 distance ≤ 0.45 조건을 적용하고 명시적 부정 지식을 사용해 잘못된 답변을 제어하려고 했습니다. 제 프로젝트에서는 파인튜닝만으로 사실 정확도를 확보하는 데 한계가 있어 RAG를 병행했습니다.

근거: 개발자 프로필 대표 프로젝트 3, 이력서 AI/ML 프로젝트. 이 문단은 2분 설명의 시작 부분입니다. 아래 사실을 확인한 뒤 완성합니다.

| 추가할 내용 | 현재 상태 |
| :--- | :--- |

| LoRA 학습 목적, 데이터 출처·규모, 학습·평가 분리 | 확인 필요 |
| 청킹 단위·크기·중첩, 거리 척도, 검색 개수 | 확인 필요 |

“3B 모델에는 RAG가 필수”라는 일반화 대신 본인 실험 조건과 관찰 결과를 설명합니다. 측정하지 않은 정확도나 사용자 수를 넣지 않습니다.

## 6. 실무 RAG POC — 약 1분 답변의 시작

> 공공기관 AI 챗봇 POC에서 Flowise AgentFlow 기반 하이브리드 검색 RAG 파이프라인의 설계와 구축을 맡았습니다. 내부 지식 베이스 검색을 개선하기 위한 검색 전략을 구성하고 검증했습니다.

근거: 경력기술서 2장. 문서에는 결합한 검색 방식과 평가 지표가 없습니다. BM25, 재순위화(Reranking), 특정 결합 알고리즘을 사용했다고 임의로 채우지 않습니다.

보충 순서: 대상 문서와 문제, 실제 검색 구성, 본인 구현 범위, 비교 실험, 관찰한 결과. 수치가 없으면 확인한 사례와 한계를 설명합니다.

## 7. 말하기 연습 기준

- 첫 문장에서 프로젝트 목적과 본인 역할을 밝힙니다.
- 상황·과제 15초, 행동 30초, 결과·한계 15초를 기본 단위로 연습합니다.
- 2분 설명은 전체 구조와 대표 문제 하나를 중심으로 구성합니다.
- “저희가”라고 말한 다음에는 본인이 직접 설계·구현·검증한 범위를 분리합니다.
- 확인되지 않은 경험은 답변 초안의 빈칸을 메운 뒤 사용합니다.
