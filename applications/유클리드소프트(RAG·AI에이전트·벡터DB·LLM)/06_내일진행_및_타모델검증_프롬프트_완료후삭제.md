```text
진행 목표는 05 문서의 빈칸을 내 실제 경험으로 채우고, 3분 포트폴리오 발표와 30분 모의면접을 완료하는 것이야. 실제 발표 시간이 따로 안내되었다면 3분은 연습 기준으로만 사용해.

다음 방식을 반드시 지켜.

- 한꺼번에 여러 질문을 하지 말고, 05 문서 3-1부터 질문을 하나씩 해.
- 내가 대답하면 내용을 `확정`, `확인 필요`, `내 담당 아님`으로 구분해 요약하고 다음 질문으로 넘어가.
- 기존 문서, 예전 대화, README의 내용을 내 실제 경험으로 간주하지 마. 내 답변과 검증 가능한 코드·실행 기록만 사용해.
- 사내 IP, 계정, 비밀번호, 고객 원문, 비공개 API 정보를 묻거나 문서에 남기지 마.
- 실무 RAG POC에서 Flowise 흐름과 검색 백엔드, 본인 구현과 타인·기존 구현을 반드시 구분해.
- LoRA는 README의 250 iterations·1e-5·80개 대화와 현재 설정·adapter의 500 iterations·2e-5·1,672건이 같은 실험인지 다른 실험인지 내게 확인해.
- 3분 발표문은 내 답변을 반영해 완성하고, 초시계로 2회 실측하도록 안내해.
- 모의면접은 질문을 한 번에 하나씩 하고, 내 답변의 수치·기술 선택·본인 담당 범위에서 꼬리질문해. 중간에 답을 알려주지 말고 30분 종료 후에 피드백해.

내가 작성한 사실과 모의면접 피드백이 모두 완성되면 01~04 문서 반영안을 제시해. 이 프롬프트는 01~04 문서 수정과, 모든 완료 조건 충족 후 05·06 임시 문서 삭제를 승인한 것으로 간주해. 다만 삭제 전에 정보가 01~04에 정상 반영됐는지, 마크다운 링크가 깨지지 않는지, `git diff --check`가 통과하는지 검증해. 완료 조건이 하나라도 남아 있으면 삭제하지 마.

읽기가 끝나면 설명을 길게 하지 말고 05 문서 3-1의 첫 질문부터 시작해.
```

## 2. 타 모델 검증용 프롬프

이 프롬프트는 수정을 맡기는 용도가 아니라, 현재 결과의 사실성·완전성을 독립적으로 검증하는 용도입니다. 아래 전체를 다른 모델의 새 대화에 복사합니다.

```text

먼저 /Users/ys/dev/resume/AGENTS.md를 전체 읽고 지침을 따라. 이 작업은 읽기 전용 검증이며 파일을 수정·생성·삭제하지 마. 정말 수정이 필요하면 먼저 문제와 근거를 보고해.

검증 대상:

- 코드·실행 자료:
  - /Users/ys/dev/ai/cookie_llm
  - /Users/ys/dev/ai/법규모니터링(AI 요약) Agents (1).json

  - /Users/ys/dev/ai/RAG/RAG_파이프라인_설계_참조문서.md

검증 절차:

1. `git status`, `git log -5 --oneline`, 면접 준비 문서가 변경된 커밋 diff를 확인해.
2. 제출본의 각 주요 주장을 01~04 면접 답변과 연결해. 주장이 누락되거나 서로 다르면 표시해.
3. 다음 항목은 반드시 원문을 열어 확인해.
   - 위니쿠키: 46개 사실 문서, bge-m3, cosine, Top-3, distance 0.45, 정보 없음 분기, 실패·잘못된 생성 사례
   - LoRA: 250 vs 500 iterations, 1e-5 vs 2e-5, 80개 대화 vs train 1,672건, YAML·adapter의 scale/dropout 충돌
   - AgentFlow: 11노드·11엣지, Input Resolver 빈 함수, 벡터 DB·검색 노드 유무, 실제 실행 근거 유무
   - 실무 RAG: Flowise에서 확인되는 흐름과 응답 구조에서 역산한 백엔드 기능을 구분. 하이브리드 검색·리랭킹을 코드로 확정할 수 있는지 판단
   - 크롤링: 79,692→514, 64,026→223, 71개 테스트, preview·rollback·commit의 실제 동작과 제출 시점 기록

4. `코드에 있음`, `저장된 실행 결과가 있음`, `실제 운영에서 검증됨`, `사용자 확인이 필요함`을 반드시 구분해.
5. 마크다운 상대 링크, `git diff --check`, 보안 민감 정보 노출 여부도 확인해.
6. 발견 내용을 심각도 순서로 정리하고 각 항목에 정확한 파일·행 번호, 원문 근거, 면접에서의 위험, 수정 방향을 제시해.

최종 보고 형식:

- 검증된 핵심 사실

- 셀프 리플렉션: 검증 중 추정했거나 증거 수준을 과대평가할 뻔한 부분

자료 경로가 없거나 회사 환경에서 접근할 수 없으면 그 항목은 `검증 불가`로 표시하고 추정하지 마. 문서는 수정하지 말고 검증 결과만 보고해.
```
