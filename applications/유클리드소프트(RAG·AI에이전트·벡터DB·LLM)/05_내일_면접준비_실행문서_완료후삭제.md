> 공공기관 RAG POC에서는 다른 담당자가 청킹하고 임베딩한 데이터를 바탕으로 AgentFlow 초안을 설계·구현했습니다. 질문 의도를 분석해 맞는 프롬프트를 가진 Agent로 연결했습니다. 하이브리드 검색은 사용했지만 검색 방식과 결합 규칙은 제 담당이 아니었습니다. 품질은 문서 기반 골든 세트 질문으로 확인했고, 월별 문서의 월을 혼동하거나 이름이 비슷한 문서를 선택하는 실패를 확인했습니다. 당시 AI 평가에는 고정 기준이 없었고, 다음에는 평가 항목과 판정 기준을 먼저 정의해야 한다고 판단했습니다.

### 2:10~2:40 위니쿠키 RAG·LoRA

> 개인 프로젝트에서는 Bllossom-3B를 MLX LoRA로 500 iterations 파인튜닝하고, 46개 사실 문서를 bge-m3와 ChromaDB로 검색했습니다. 활성 서버 기준은 cosine distance 0.45입니다. 위치 문서를 찾고도 0.4797이라 거절한 사례와, 3,500원 근거를 찾고도 3,700원으로 생성한 사례를 확인했습니다. 임계값과 생성 품질을 별도로 평가해야 한다는 한계도 배웠습니다.

### 2:40~3:00 지원 직무와의 연결

> 저는 데이터 수집·정제·적재부터 RAG AgentFlow까지 연결한 경험이 있습니다. 유클리드소프트에서도 데이터 파이프라인과 Agent 설계 업무에 먼저 기여하고, 검색·응답 품질을 객관적으로 평가하는 역량까지 확장하겠습니다.
