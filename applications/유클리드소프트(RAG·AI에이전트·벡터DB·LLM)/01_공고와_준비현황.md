## 3. 공고와 경험의 연결

판단: 데이터 수집·정제 경험을 RAG 시스템 개발로 연결할 수 있는 공고입니다. 실제 업무 배분은 확인이 필요합니다.

| 공고 항목 | 문서에서 확인한 근거 | 보충하거나 확인할 항목 |
| :--- | :--- | :--- |
| Python 개발 | 수집·첨부 추출·적재, DDL 생성, 단위 테스트 71개 | 직접 설명 가능한 함수와 테스트 사례 |
| 머신러닝 기본 이론 | Kaggle 분류·회귀·NLP·딥러닝 프로젝트 | 데이터 분리, 과적합, 지표를 실제 프로젝트로 설명 |
| 데이터 분석·전처리·EDA | 실무 수집·정제, Kaggle 전처리, 마트·대시보드 | EDA에서 발견한 문제와 처리 결정 사례 |
| 기술 문서 작성 | 경력·프로젝트 문서 존재 | 협업에 사용한 기술 문서와 독자, 전달 결과 |
| 문제 해결 커뮤니케이션 | 입력 컨텍스트 실측과 장애 원인 규명 | 동료·운영 담당자에게 설명하고 합의한 사례 |
| RAG·LLM 프레임워크 | Flowise AgentFlow, 개인 FastAPI RAG | 실제 검색 구성, 코드와 설정의 담당 범위 |
| 벡터 DB·임베딩 | ChromaDB, bge-m3 | 청킹, 거리 척도, 문서 갱신, 인덱싱, 운영 규모 |

| 검색·응답 품질 평가 | 검색 정확도 개선 서술, distance ≤ 0.45 | 평가 질문, 정답 근거, 임계값 선정, 개선 전후 결과 |
| Git 협업·CI/CD | Git/GitHub 스택과 저장소 링크 | PR·리뷰·자동 배포 경험은 확인 필요 |
| Docker·Kubernetes | 기본 문서에서 근거 부족 | 실제 사용 여부와 배포 범위 확인 필요 |
| 폐쇄망·온프레미스 AI | 로컬 MLX·Ollama, Rocky 운영 및 환경 대응 서술 | 폐쇄망 LLM 배포·모델 반입·운영 경험은 별도 확인 필요 |

반복·강조 키워드: RAG, 에이전트, 데이터 파이프라인, 임베딩, 검색 품질, 실험·평가.
